# 边界判定规则

用于回答一个问题：**"这个不确定项，需要中断去问吗？"**

## 三步判定流程

1. **能不能自己解决？**
   能否通过检索、读取文件、运行工具、查看已有上下文来确认？
   能 → 自己确认，不提问。
   不能 → 进入第 2 步。

2. **答案会不会实质改变产出？**
   不同答案是否会导致不同的结论、结构、技术选型、范围或不可逆后果？
   不会（只是换个措辞、换个文件名）→ 用可逆默认值继续，并标注假定。
   会 → 进入第 3 步。

3. **这个答案是否只有用户（或用户侧的人/系统）能提供？**
   是 → **中断提问**。
   否（只是自己没去查）→ 回到第 1 步。

一句话版本：**答案是只有用户能给的，且会改变结果 → 必须问。**

## 四类阻塞项的识别要点

### 1. 背景缺失

典型信号：要写方案却不知道业务目标/受众/成功标准；要改代码却不知道运行环境与约束。

判断要点：缺的不是"细节"，而是**会决定整体走向的前提**。

### 2. 需人工查询

典型信号：需要线上配置、他人负责的数据、用户专属信息、用户本地文件内容。

判断要点：**不要用"指导用户分情况处理"来替代获取答案**。

### 3. 上下文外知识

典型信号：需要某个内部系统的当前行为、内部约定、私有接口细节，且无法验证。

判断要点：区分"我可以通过搜索/读文件确认"与"只有内部人知道"。前者自己去查，后者去问。**不要凭记忆编造内部细节。**

### 4. 实质歧义与关键参数

典型信号：同一句话有多个合理理解；或动作不可逆（删除、覆盖、发送、发布、付费、改配置）而关键参数未定。

判断要点：不可逆动作永远先确认，即使看起来"理应如此"。

## 易误判情形

| 情形 | 判定 | 理由 |
|---|---|---|
| 用户要"一份周报"，但没说字数/模板 | 不中断，用合理默认格式，标注可调整 | 形式偏好，可低成本回改 |
| 用户要"评估方案 A 和 B" | 不中断，直接对比 | 分支枚举本身就是交付物 |
| 用户要"加个自动回复"，但没说走哪个 IM 渠道、后端在哪 | 中断提问 | 决定技术方案，属实质歧义 |
| 用户说"同步数据过去"，但没说源/目标/频率，且涉及覆盖 | 中断提问 | 不可逆 + 关键参数缺失 |
| 用户说"你看着办" | 不中断，用默认值推进并标注假定 | 已获授权；但不可逆动作仍需确认 |
| 缺少能搜索到或从文件读到的信息 | 不中断，自己去查 | 自己能解决的不该占用用户时间 |
| 用户明确说"把各种情况都列出来" | 不中断，展开多分支 | 用户显式要求 |
| 需要用户回答"你们内部接口的鉴权方式是哪种" | 中断提问 | 上下文外、无法验证的内部知识 |
| 因缺少信息而打算先给"占位版本" | 中断提问 | 未经授权的降级交付 |

## 提问质量要求

- **一次问最关键的一个**：优先单问题；最多 3 个。超过 3 个说明还没想清楚真正卡点。
- **可回答**：问题要能被一句话或一个选项回答。
- **带方向提示**：说明"不同答案会把方向带到哪里"，但只给一句话。
- **给"由你决定"选项**：允许用户把决定权交回给你。
- **说清必要性**：让用户知道为什么必须问。
